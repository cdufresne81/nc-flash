# TCM table layouts (LFG1TF000)

How the NC automatic-transmission controller stores its lookup tables, derived
from the code in `examples/LFG1TF000.bin` on Nov 9, 2026 (issue #123). Read this
before adding or changing a table in `LFG1TF000_v02.xml` / `LFG1TG000_v02.xml`.

## The three record layouts

Every lookup table in the calibration area (0x70000-0x77FFF) is a
self-describing record. The code passes the address of the record's first byte
to one of three library routines:

| Routine | Record layout | Cell size | In the definition |
|---------|---------------|-----------|-------------------|
| 0x10764 (worker 0x10922) | `[count u8][axis: count x u8][data: count x u8]` | 1 byte | `type="2D"`, axis at record+1, data at record+1+count, both uint8 |
| 0x1078A | `[cols u8][rows u8][X axis: cols x u8]` then `rows` x `[Y u8][data: cols x u8]` | 1 byte | `type="3D" layout="interleaved"`, address = the record |
| 0x108E6 (worker 0x10A48) | `[count u16][u16][axis: count x u16][data: count x u16]` | 2 bytes | `type="2D"`, axis at record+4, data at record+4+2*count, both uint16 |

Evidence for the cell sizes: 0x10922 loads every axis and data cell with
`mov.b` and shifts it left 8 (the result is the byte value x 256); 0x1078A does
the same for its row and column cells; 0x108E6 reads its count with `mov.w`, and its
worker reads the axis and data cells with `mov.w` at 2-byte steps.

The second word of a word record (record+2) is passed to a second routine after
the lookup; its meaning is not derived yet.

Records are often stored back to back and indexed (for example by gear): the
code loads the address of the first one and adds `index x record size`. The
record size then confirms the cell size on its own (a 5-point byte record is
11 bytes: 1 + 5 + 5).

## What a count byte does NOT prove

The definitions were first generated by scanning for "a small number followed
by rising values". That finds real records, and also:

- scalars whose first byte happens to be small (`03 00` is the word 0x0300,
  not a 3-point table);
- a row of a 2-D map read as a 1-D record;
- a 1-D record whose first axis value was read as a row count.

So a table is only trusted when the code passes its record address to one of
the three routines above. `docs/internal/tcm_table_evidence.csv` lists that
evidence for every table changed under #123, and the real address and access
width of the 49 entries that were removed because they are not tables. Those
values are still calibration data: define them again as scalars once their
meaning is derived.

## LFG1TG000

No LFG1TG000 dump has been checked. Its definition is a copy of LFG1TF000's
with the ID changed, and a test keeps the two identical. Treat every
LFG1TG000 address as unverified.

## Checks

- `python tools/metadata_lint.py check` fails on overlapping tables and on
  16-bit cells at odd addresses (no TCM exceptions remain in the baseline).
- `tests/test_tcm_table_layouts.py` compares every one-axis table with the
  count stored in the dump and with the cell size its routine reads.
